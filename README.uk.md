# VSCplugin (VSCpy) — Технічна документація

## Огляд

VSCplugin — це плагін файлової системи (WFX) для Total Commander, який
робить доступними для перегляду тіньові копії томів Windows (точки
відновлення). Він показує їх як віртуальний мережевий диск "VSCpy":

```
\\VSCpy\<диск>\<часова мітка знімка>\<звичайна структура папок>
```

З цих знімків можна копіювати файли (лише для читання) — наприклад, щоб
відновити випадково перезаписаний або видалений файл — без виконання
повного відновлення системи.

Додатковий стовпець **"VSCStatus"** показує для кожного файлу, чи
змінився він порівняно з попереднім знімком.

## Архітектура

Плагін являє собою одну DLL (`VSCPlugin.wfx64`), розділену на такі
вихідні модулі:

- `common/vss_enum.*` — отримує список наявних тіньових копій через WMI
  (`Win32_ShadowCopy`, простір імен `ROOT\CIMV2`).
- `common/pathutil.*` — перетворює віртуальні шляхи TC
  (`\<диск>\<часова мітка>\<решта>`) у реальні шляхи пристроїв
  (`\\?\GLOBALROOT\Device\HarddiskVolumeShadowCopyN\<решта>`).
- `common/diff.*` — власне логіка порівняння (див. нижче).
- `common/debuglog.h` — опційне налагоджувальне логування, що вмикається
  через ini-файл.
- `wfx/vscplugin.cpp` — сама реалізація WFX (`FsInitW`,
  `FsFindFirstW`/`FsFindNextW`/`FsFindClose`, `FsGetFileW`), а також
  стовпець статусу (`FsContentGetSupportedField`, `FsContentGetValueW`).

## Як саме працює логіка порівняння (diff)

Логіка порівняння міститься в `common/diff.cpp`, функція
`ComputeStatus`.

**Основний принцип: порівняння завжди відбувається з безпосередньо
попереднім (найближчим старішим) знімком того самого диска — а не з
фіксованим "першим" чи "оригінальним" знімком.**

1. Усі знімки диска сортуються за датою створення в порядку спадання
   (спочатку найновіший) — `ListShadowCopiesForDrive`.
2. Визначається позиція поточного переглядуваного знімка в цьому списку.
3. **Базовий знімок** — це наступний елемент у відсортованому списку
   (тобто безпосередньо попередній за часом).
4. Файл/папка шукається за тим самим відносним шляхом у базовому знімку.

**Приклад із трьома знімками A (найстаріший) → B → C (найновіший):**

| Ви переглядаєте | Порівняння з                                             |
| --------------- | -------------------------------------------------------- |
| C               | B                                                        |
| B               | A                                                        |
| A               | — (немає базового знімка, стовпець залишається порожнім) |

**Критерії оцінки** (лише для файлів, не для папок):

- Файл відсутній у базовому знімку → **«Новий»**
- Файл існує в обох, але розмір або `LastWriteTime` відрізняються →
  **«Змінено»**
- Розмір і `LastWriteTime` однакові → **«Без змін»**

Для **папок** перевіряється лише сам факт наявності в базовому знімку
(без рекурсивного порівняння вмісту, з міркувань продуктивності) —
наявна папка завжди вважається «Без змін», нова — «Новий».

## Відоме обмеження: немає підтримки 32-біт

Плагін свідомо постачається **лише у 64-бітній версії**
(`VSCPlugin.wfx64`).

Причина: клас WMI `Win32_ShadowCopy`, через який ми отримуємо список
наявних знімків, офіційно задокументований Microsoft як **недоступний
для 32-бітних застосунків на 64-бітній Windows**. При цьому 32-бітний
процес не отримує помилку, а тихо отримує порожній результат — саме це
ми й спостерігали під час тестування на реальній 32-бітній установці
Total Commander (WMI-запит виконувався успішно, але повертав 0
результатів, хоча `vssadmin list shadows` показував реальні знімки).

Джерело: Microsoft Learn, *Win32_ShadowCopy class*, розділ "Remarks":

> "This class is unavailable for 32-bit applications on Windows Server
> 2008 x64."

<https://learn.microsoft.com/en-us/previous-versions/windows/desktop/vsswmi/win32-shadowcopy>

Допоміжний 64-бітний процес, який виконував би WMI-запит від імені
32-бітної установки Total Commander, був технічно можливий, але свідомо
не був реалізований (співвідношення складності й користі).

## Налагоджувальне логування

За замовчуванням вимкнено (жодного звернення до диска). Щоб увімкнути,
створіть файл `VSCDebug.ini` у тій самій папці, що й `VSCPlugin.wfx64`:

```ini
[Debug]
Enabled=1
```

Перезапустіть Total Commander (налаштування перевіряється лише під час
завантаження DLL). Лог записується у файл `VSCPlugin_debug.log` у тій
самій папці.

## Збірка

Крос-компіляція через MinGW-w64 (`x86_64-w64-mingw32-g++`), C++17.

Важливі прапорці лінкера:

```
-static-libgcc -static-libstdc++
```

Без цих прапорців DLL динамічно залежить від `libgcc_s_*.dll` /
`libstdc++-6.dll`, яких немає у звичайній системі Windows — у такому
разі TC повідомляє «плагін не розпізнано» замість зрозумілої помилки
завантаження.

Бібліотеки, потрібні під час лінкування: `-lwbemuuid -lole32 -loleaut32`
(для WMI-запиту).
