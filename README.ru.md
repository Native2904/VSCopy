## Обзор

VSCplugin — это плагин файловой системы (WFX) для Total Commander,
который делает доступными для просмотра теневые копии томов Windows
(точки восстановления). Он показывает их как виртуальный сетевой диск
"VSCpy":

```
\\VSCpy\<диск>\<временная метка снапшота>\<обычная структура папок>
```

Из этих снапшотов можно скопировать файлы (только для чтения) — например,
чтобы восстановить случайно перезаписанный или удалённый файл — без
выполнения полного восстановления системы.

Дополнительный столбец **"VSCStatus"** показывает для каждого файла,
изменился ли он по сравнению с предыдущим снапшотом.

## Архитектура

Плагин представляет собой одну DLL (`VSCPlugin.wfx64`), разделённую на
следующие исходные модули:

- `common/vss_enum.*` — получает список существующих теневых копий через
  WMI (`Win32_ShadowCopy`, пространство имён `ROOT\CIMV2`).
- `common/pathutil.*` — преобразует виртуальные пути TC
  (`\<диск>\<временная метка>\<остальное>`) в реальные пути устройств
  (`\\?\GLOBALROOT\Device\HarddiskVolumeShadowCopyN\<остальное>`).
- `common/diff.*` — собственно логика сравнения (см. ниже).
- `common/debuglog.h` — опциональное отладочное логирование, включаемое
  через ini-файл.
- `wfx/vscplugin.cpp` — сама реализация WFX (`FsInitW`,
  `FsFindFirstW`/`FsFindNextW`/`FsFindClose`, `FsGetFileW`), а также
  столбец статуса (`FsContentGetSupportedField`, `FsContentGetValueW`).

## Как именно работает логика сравнения (diff)

Логика сравнения находится в `common/diff.cpp`, функция `ComputeStatus`.

**Основной принцип: сравнение всегда идёт с непосредственно
предшествующим (ближайшим более старым) снапшотом того же диска — а не
с фиксированным "первым" или "исходным" снапшотом.**

1. Все снапшоты диска сортируются по дате создания в порядке убывания
   (сначала новейший) — `ListShadowCopiesForDrive`.
2. Определяется позиция текущего просматриваемого снапшота в этом
   списке.
3. **Базовый снапшот** — это следующий элемент в отсортированном
   списке (то есть непосредственно предшествующий по времени).
4. Файл/папка ищется по тому же относительному пути в базовом снапшоте.

**Пример с тремя снапшотами A (самый старый) → B → C (самый новый):**

| Вы просматриваете | Сравнение с                                        |
| ----------------- | -------------------------------------------------- |
| C                 | B                                                  |
| B                 | A                                                  |
| A                 | — (нет базового снапшота, столбец остаётся пустым) |

**Критерии оценки** (только для файлов, не для папок):

- Файл отсутствует в базовом снапшоте → **«Новый»**
- Файл существует в обоих, но размер или `LastWriteTime` отличаются →
  **«Изменён»**
- Размер и `LastWriteTime` совпадают → **«Без изменений»**

Для **папок** проверяется только сам факт наличия в базовом снапшоте
(без рекурсивного сравнения содержимого, из соображений
производительности) — существующая папка всегда считается «Без
изменений», новая — «Новый».

## Известное ограничение: нет поддержки 32-бит

Плагин сознательно распространяется **только в 64-битной версии**
(`VSCPlugin.wfx64`).

Причина: класс WMI `Win32_ShadowCopy`, через который мы получаем список
существующих снапшотов, официально задокументирован Microsoft как
**недоступный для 32-битных приложений на 64-битной Windows**. При этом
32-битный процесс не получает ошибку, а тихо получает пустой результат —
именно это мы и наблюдали при тестировании на реальной 32-битной
установке Total Commander (WMI-запрос выполнялся успешно, но возвращал
0 результатов, хотя `vssadmin list shadows` показывал реальные снапшоты).

Источник: Microsoft Learn, *Win32_ShadowCopy class*, раздел "Remarks":

> "This class is unavailable for 32-bit applications on Windows Server
> 2008 x64."

<https://learn.microsoft.com/en-us/previous-versions/windows/desktop/vsswmi/win32-shadowcopy>

Вспомогательный 64-битный процесс, который выполнял бы WMI-запрос от
имени 32-битной установки Total Commander, был технически возможен, но
сознательно не был реализован (соотношение сложности и пользы).

## Отладочное логирование

По умолчанию отключено (никакого обращения к диску). Чтобы включить,
создайте файл `VSCDebug.ini` в той же папке, что и `VSCPlugin.wfx64`:

```ini
[Debug]
Enabled=1
```

Перезапустите Total Commander (настройка проверяется только при загрузке
DLL). Лог записывается в файл `VSCPlugin_debug.log` в той же папке.

## Сборка

Кросс-компиляция через MinGW-w64 (`x86_64-w64-mingw32-g++`), C++17.

Важные флаги линковщика:

```
-static-libgcc -static-libstdc++
```

Без этих флагов DLL динамически зависит от `libgcc_s_*.dll` /
`libstdc++-6.dll`, которых нет на обычной системе Windows — в этом
случае TC сообщает «плагин не распознан» вместо понятной ошибки загрузки.

Библиотеки, необходимые при линковке: `-lwbemuuid -lole32 -loleaut32`
(для WMI-запроса).
